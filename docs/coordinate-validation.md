# 坐标验证

离线测试日期：2026-09-11；真实 API 验证日期：2026-09-12。记录分为离线算法测试和真实 POI/底图验收。

## 离线算法回归（已通过）

以下是代码测试用控制点，不是从高德获取的真实 POI。所有坐标均按 `经度,纬度` 排列。

| 城市 | WGS-84 输入          | 转换后的 GCJ-02            | 转回 WGS-84 数值残差 |
| ---- | -------------------- | -------------------------- | -------------------- |
| 北京 | 116.397128,39.916527 | 116.403372494,39.917930749 | <0.000001 m          |
| 上海 | 121.473700,31.230400 | 121.478223059,31.228457738 | <0.000001 m          |
| 西安 | 108.939800,34.341600 | 108.944455634,34.340044496 | <0.000001 m          |
| 深圳 | 114.057900,22.543100 | 114.063013999,22.540382814 | <0.000001 m          |
| 广州 | 113.264400,23.129100 | 113.269729592,23.126423340 | <0.000001 m          |
| 成都 | 104.066500,30.572800 | 104.069004928,30.570345720 | <0.000001 m          |

反算最多迭代 30 次，偏差阈值 1e-9 度；表中误差基于未舍入值，以角度差乘 111320 估算上界。正向转换也有固定北京回归向量，防止正逆同时出错却通过 round-trip。另测试海南在范围内，香港、澳门、台北、东京、首尔、河内、加德满都、乌兰巴托、海参崴、伦敦和 0,0 原样返回。

这些极小残差只说明数值反算一致，**不代表亚毫米测绘精度**。GCJ 算法是近似模型，地图底图、POI 锚点、建筑入口和地理边界还会造成误差。城市真实地点目标是数米级，需要下节实测。

执行 `npm run smoke` 后，`docs/smoke-results.json` 会记录十个目标的实际原始和转换坐标、地点 ID、名称、地址及 OSM 对照链接，`visualVerification` 和 `trekSaveAndRestart` 初始仍为 pending。失败会记录状态且脚本非零退出。

人工验收步骤：

1. 在 TREK 的 OpenFreeMap 底图打开记录的 WGS-84 坐标，与建筑/场地位置比较；同时打开原 GCJ-02 坐标作偏移对照。
2. 区分入口与建筑中心的正常 POI 差异，以及成片方向一致的几百米 GCJ 偏移；保存截图、地图缩放级别和检查日期。
3. 检查十个目标的中文名称、地址、自动补全，以及点击提示后详情。
4. 保存地点，关闭后重开；重启 TREK 与 Adapter 后再次打开。
5. 更新本文件真实坐标、误差判断和结果。不要用离线控制点覆盖这些空白。

## 转换范围限制

使用 Natural Earth 1:10m CHN 多边形作运行范围判断，包含海南，排除港澳台。数据来源和授权见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。它有比例尺概化、海岸线时效和小岛遗漏，尤其填海区与深圳湾口岸应额外验证。

边界附近 GCJ 偏移本身可能跨过多边形，故范围判断无法做到测绘级精确。反算迭代固定首次判断，避免迭代过程反复切换范围；仍不能保证边界两侧的 round-trip。未来如实测发现此类 POI，应在有证据的情况下结合高德行政区信息细化判定。
